### 今天学习的 git 命令
| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `git clone <仓库地址>` | 将远程仓库复制到本地 | 第一次获取已有远程项目时 |

| `git add .` | 暂存当前目录中的所有修改 | 准备提交全部修改时 |
| `git add <文件路径>` | 暂存指定文件 | 只想提交某个文件时 |
| `git commit -m "提交说明"` | 创建一条本地提交记录 | 完成一次修改并暂存后 |
| `git checkout -b <分支名>` | 创建并切换到新分支 | 开始开发新功能时 |
| `git checkout main` | 切换到主分支 | 准备比较或合并功能分支时 |
| `git branch -d <分支名>` | 删除已经合并的本地分支 | 功能分支不再需要时 |
| `git log --oneline` | 简洁地查看提交历史 | 查看提交顺序或准备回退时 |
| `git diff main <分支名>` | 比较两个分支的代码差异 | 合并分支前检查修改时 |

| `git push` | 将本地提交推送到远程 | 日常上传已经提交的修改时 |

### 作业 2：认识编译产物
在 `MDK-ARM` 目录里找到 `.o`、`.axf`、`.hex` 文件，回答：
1. `F7` 完成了哪几步？
预处理：处理 #include、#define 和条件编译等内容
`编译`：把每个 .c 文件转换成机器相关的目标文件 .o 文件
`汇编`：把启动文件等 .s 汇编文件转换成 .o 文件
`链接`：把所有 .o 文件和需要的库组合起来，生成 .axf 可执行映像
`生成 HEX`：如果工程开启了“Create HEX File”，Keil 会从链接结果生成 .hex 文件   
.c 文件先被编译为 .o 文件，所有目标文件再经过链接生成 .axf，需要时还可以生成 .hex。Keil 通过 ST-Link 将程序映像写入 STM32 的 Flash。
2. `F8` 把什么文件写进了芯片？
F8 将 .axf 中的可加载程序数据，通过 ST-Link 写入芯片中。   
3. 为什么改完代码必须重新编译再下载？
因为芯片不能直接执行 .c 文件，只能执行机器指令。修改 .c 文件以后，原来的 .o、.axf 和 .hex 仍然对应旧代码。必须重新编译和链接，才能生成包含新代码的程序映像；然后重新下载，芯片 Flash 中的旧程序才会被新程序替换。只修改代码但不重新编译，下载的仍可能是旧程序；只编译但不重新下载，芯片里运行的也仍然是旧程序。
`修改源代码 - 编译 - 链接 - 生成程序映像 - 下载到 Flash - 复位运行`

| 文件 | 含义 |
|---|---|
| .o | 单个源文件编译后得到的目标文件，还不能单独烧录运行 |
| .axf | 链接后的完整程序映像，通常还包含调试符号 |
| .hex | 用十六进制文本格式保存的可烧录程序数据 |

#### 任务 3.1：把新组件添加进工程
先完成 `user` 组件的添加，再在 `main.c` 里补上 include：
1. 在 Keil 里新建一个 Group，命名为 `user`；
2. 把 `user/src/user_beep.c` 添加进这个 Group；
3. 在 `Options for Target -> C/C++ -> Include Paths` 里加上 `..\user\inc`；
4. 打开 `Core/Src/main.c`，把 `// 在这里替换成#include user_beep.h` 这行改成 `#include "user_beep.h"`；
5. 按 `F7` 编译，按 `F8` 下载，复位后听蜂鸣器是不是按“长-短-短”响三次。
按了复位后确实响了。
main.c 中有一个空的弱函数：
```bash
__weak void user_beep()
{
}
```
并在初始化后调用：
```bash
buzzer_init();
user_beep();
```
没有加入 user_beep.c 时，执行的是这个空函数，所以没有声音。当工程加入 user/src/user_beep.c 后，
```bash
void user_beep(void)
{
    /* 第一声：长音 */
    buzzer_on();
    HAL_Delay(USER_BEEP_LONG_MS);
    buzzer_off();
    HAL_Delay(USER_BEEP_GAP_MS);
    /* 第二声：短音 */
    buzzer_on();
    HAL_Delay(USER_BEEP_SHORT_MS);
    buzzer_off();
    HAL_Delay(USER_BEEP_GAP_MS);
    /* 第三声：短音 */
    buzzer_on();
    HAL_Delay(USER_BEEP_SHORT_MS);
    buzzer_off();
    HAL_Delay(USER_BEEP_GAP_MS);
}
```
由于这个定义不是 __weak，链接器会用它替换 main.c 中的弱定义。芯片复位后，user_beep() 就会执行真正的长短蜂鸣代码。
更多代码解释：[代码学习.md](代码学习.md)
