### 今天学习的 git 命令
| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `git clone <仓库地址>` | 将远程仓库复制到本地 | 第一次获取已有远程项目时 |
| `git init` | 在当前目录初始化 Git 仓库 | 本地已有项目，需要开始使用 Git 管理时 |
| `git status` | 查看仓库、暂存区和文件状态 | 提交前后检查文件变化时 |
| `git add .` | 暂存当前目录中的所有修改 | 准备提交全部修改时 |
| `git add <文件路径>` | 暂存指定文件 | 只想提交某个文件时 |
| `git commit -m "提交说明"` | 创建一条本地提交记录 | 完成一次修改并暂存后 |
| `git checkout -b <分支名>` | 创建并切换到新分支 | 开始开发新功能时 |
| `git checkout main` | 切换到主分支 | 准备比较或合并功能分支时 |
| `git branch -d <分支名>` | 删除已经合并的本地分支 | 功能分支不再需要时 |
| `git log --oneline` | 简洁地查看提交历史 | 查看提交顺序或准备回退时 |
| `git diff main <分支名>` | 比较两个分支的代码差异 | 合并分支前检查修改时 |
| `git merge <分支名>` | 将指定分支合并到当前分支 | 把功能分支合并回 `main` 时 |
| `git reset --hard HEAD~1` | 回退到上一个提交并丢弃修改 | 确认不需要最后一次提交时，谨慎使用 |
| `git remote add origin <仓库地址>` | 关联远程仓库 | 本地仓库第一次连接 GitHub 时 |
| `git remote -v` | 查看远程仓库地址 | 检查远程仓库是否配置正确时 |
| `git push -u origin main` | 首次推送并建立分支跟踪关系 | 第一次将 `main` 推送到远程时 |
| `git push` | 将本地提交推送到远程 | 日常上传已经提交的修改时 |
| `git pull` | 获取并合并远程更新 | 远程仓库有新提交，需要同步到本地时 |

### 作业 2：认识编译产物
在 `MDK-ARM` 目录里找到 `.o`、`.axf`、`.hex` 文件，回答：
1. `F7` 完成了哪几步？
预处理：处理 #include、#define 和条件编译等内容
编译：把每个 .c 文件转换成机器相关的目标文件 .o 文件
汇编：把启动文件等 .s 汇编文件转换成 .o 文件
链接：把所有 .o 文件和需要的库组合起来，生成 .axf 可执行映像
生成 HEX：如果工程开启了“Create HEX File”，Keil 会从链接结果生成 .hex 文件   
.c 文件先被编译为 .o 文件，所有目标文件再经过链接生成 .axf，需要时还可以生成 .hex。Keil 通过 ST-Link 将程序映像写入 STM32 的 Flash。
2. `F8` 把什么文件写进了芯片？
F8 将 .axf 中的可加载程序数据，通过 ST-Link 写入芯片中。   
3. 为什么改完代码必须重新编译再下载？
因为芯片不能直接执行 .c 文件，只能执行机器指令。修改 .c 文件以后，原来的 .o、.axf 和 .hex 仍然对应旧代码。必须重新编译和链接，才能生成包含新代码的程序映像；然后重新下载，芯片 Flash 中的旧程序才会被新程序替换。只修改代码但不重新编译，下载的仍可能是旧程序；只编译但不重新下载，芯片里运行的也仍然是旧程序。
修改源代码 - 编译 - 链接 - 生成程序映像 - 下载到 Flash - 复位运行

| 文件 | 含义 |
|---|---|
| .o | 单个源文件编译后得到的目标文件，还不能单独烧录运行 |
| .axf | 链接后的完整程序映像，通常还包含调试符号 |
| .hex | 用十六进制文本格式保存的可烧录程序数据 |
### 作业 3：配置工程（重点）
这个作业分两个任务：先把 `user` 组件添加进工程，再把已经在工程里的 `hardware` 文件移除，编译看报什么错。
答：
#### 任务 3.1：把新组件添加进工程
先完成 `user` 组件的添加，再在 `main.c` 里补上 include：
1. 在 Keil 里新建一个 Group，命名为 `user`；
2. 把 `user/src/user_beep.c` 添加进这个 Group；
3. 在 `Options for Target -> C/C++ -> Include Paths` 里加上 `..\user\inc`；
4. 打开 `Core/Src/main.c`，把 `// 在这里替换成#include user_beep.h` 这行改成 `#include "user_beep.h"`；
5. 按 `F7` 编译，按 `F8` 下载，复位后听蜂鸣器是不是按“长-短-短”响三次。
按了复位后确实响了。
#### 任务 3.2：移除已经在工程里的 hardware 文件，编译看报错
工程里已经配置了 `hardware` 组件：`hardware/src/buzzer.c`、`led.c` 在 `hardware` Group 里，`hardware/inc` 在 Include Paths 里。现在分别把它们移除，每移一项都按 `F7` 编译，记下报错再恢复：
移除 Include Paths 里的 `..\hardware\inc`：
../hardware/src/buzzer.c(5): error: 'buzzer.h' file not found
编译报找不到 `buzzer.h` / `led.h` 之类的头文件错误；
移除 `hardware` Group 里的 `buzzer.c` 和 `led.c`：
keil_proj_demo\keil_proj_demo.axf: Error: L6218E: Undefined symbol buzzer_init (referred from main.o).
keil_proj_demo\keil_proj_demo.axf: Error: L6218E: Undefined symbol led_on (referred from main.o).
keil_proj_demo\keil_proj_demo.axf: Error: L6218E: Undefined symbol led_off (referred from main.o).
keil_proj_demo\keil_proj_demo.axf: Error: L6218E: Undefined symbol buzzer_on (referred from main.o).
keil_proj_demo\keil_proj_demo.axf: Error: L6218E: Undefined symbol buzzer_off (referred from main.o).
链接时报 `Undefined symbol`，因为函数实现没了。
Include Paths 负责让编译器找到 `.h` 头文件，Group 里的 `.c` 负责提供函数实现，两者缺一不可。

1. 遇到的报错和解决办法

| 问题                       | 可能原因                   | 解决办法                                  |
| ------------------------ | ---------------------- | ------------------------------------- |
| 找不到 `buzzer.h` 或 `led.h` | `buzzer.h` 或 `led.h`文件被删除    | 添加`buzzer.h` 或 `led.h`                  |
| 找不到 `user_beep.h`        | 没有配置 `user/inc`        | 添加 `..\user\inc`                      |
| 出现 `Undefined symbol`    | 对应的 `.c` 文件没有加入工程      | 把实现文件加入相应的 Group                      |
| 编译成功但 `user_beep()` 没有声音 | 仍在使用 `__weak` 空实现      | 添加 `user/src/user_beep.c`，然后重新编译并下载   |
| 无法下载程序                   | ST-Link 驱动、接线或下载配置存在问题 | 检查 ST-Link 驱动、SWD 接线、开发板供电以及 Debug 设置 |
| 修改代码后现象没有变化              | 没有重新编译或下载              | 再次执行 `F7`、`F8`，然后复位开发板                |
| 没有生成 `.hex` 文件           | 没有开启 HEX 文件输出          | 在 Output 设置中勾选 `Create HEX File`      |
